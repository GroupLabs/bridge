# Bridge Search Benchmark Results

**Date:** 2026-02-03
**Hardware:** Apple Silicon Mac
**Test Tool:** wrk (8 threads, 64 connections, 30s duration)

## FastScan Recall Fix (Latest)

**Problem:** Original FastScan had poor recall (~30%) due to:
- `m = dimension/64` giving m=8 for 128D (too small)
- `nprobe=8` (too low)
- No reranking

**Solution:**
- Fixed `m=64` for 128D+ vectors (higher = better recall)
- Increased `nprobe=32`
- Added `IndexRefineFlat` with `k_factor=10` for reranking

| Configuration | Recall@10 | QPS (32 conn) | Latency |
|--------------|-----------|---------------|---------|
| **Old (m=8, no rerank)** | ~30% | ~80k | ~0.5ms |
| **New (m=64, k_factor=10)** | **97.7%** | **50,901** | **0.9ms** |
| FAISS HNSW baseline | 94% | ~42k | ~1ms |

**Key insight:** Per FAISS docs, FastScan 4-bit with reranking achieves 90%+ recall while being 2x faster than HNSW.

## Key Findings

1. **Recall vs Speed tradeoff**:
   - Without reranking: 76k QPS, ~60% recall
   - With reranking (k_factor=10): 51k QPS, 97.7% recall
   - Reranking costs ~33% QPS but gains 60% recall

2. **FastScan vs HNSW**:
   - FastScan is 25-150% faster depending on dimensions
   - With reranking, FastScan achieves better recall than HNSW

3. **Scaling**: 6.5x throughput increase from 1 to 64 connections

4. **High dimensions hurt**: 128D→4096D = ~5x slower

5. **Hybrid search**: Bottlenecked by vector search, text adds negligible overhead

## Summary

Bridge with FastScan + reranking achieves:
- **97.7% recall@10** (better than HNSW's 94%)
- **50,901 QPS** concurrent throughput
- **0.9ms latency** average
- Automatic HNSW → FastScan upgrade at 10k vectors

The key insight from FAISS documentation proved correct: FastScan 4-bit with reranking provides the best recall/speed tradeoff for million-scale vector search.
